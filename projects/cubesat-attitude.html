Overview

Built as a controls tool, not just a plot generator

The core idea behind this project was to make spacecraft attitude control tangible. Rather than leaving the work as disconnected scripts, the simulator organizes rigid-body dynamics, controller tuning, visualization, and robustness assessment into a single interactive app that can be used both for analysis and for demonstration.

That matters because attitude-control problems are usually easier to understand when the state, torque limits, transient response, and body motion are all visible at the same time. This project was built around that idea: every mode exposes both the mathematics and the physical behavior of the CubeSat.

1-axis mode

Uses a simple rotational state [theta, omega] to study commanded versus saturated torque, angular-rate damping, and single-axis pointing recovery.

3-axis mode

Propagates a quaternion-plus-rate state, computes body torques from attitude error and rate feedback, and animates the full CubeSat body frame in 3D.

Monte Carlo mode

Randomizes initial Euler angles and angular rates, then aggregates final pointing error and settling behavior to move from one run to controller robustness.

Dynamics Model

What is being integrated in each mode

The one-axis model solves a classic rigid-body attitude problem with angular position and angular velocity as the state. It integrates thetaDot = omega and omegaDot = (tauControl + tauDisturbance) / I, where the control torque is generated by a PD law and then clipped by a hard actuator limit.

The three-axis model moves to quaternion kinematics and Euler rigid-body dynamics. The state is [q0 q1 q2 q3 wx wy wz], with quaternion propagation qDot = 0.5 * Omega(w) * q and rotational dynamics wDot = J^-1 (tauTotal - w x (J w)). The implementation renormalizes the quaternion and flips its sign when needed so the controller always uses the shortest-rotation representation.

  • The default one-axis inertia is 0.02 kg*m^2 with a 25 degree initial angular offset and a maximum control torque of 0.001 N*m.
  • The default three-axis inertia matrix is diagonal with Jx = 0.020, Jy = 0.025, and Jz = 0.015 kg*m^2, which creates axis-dependent rotational response.
  • The one-axis disturbance is sinusoidal in time, while the three-axis disturbance injects time-varying body torques through a vector of sinusoidal and constant components scaled by the disturbance amplitude.
  • Both modes are integrated with ode45, which keeps the app numerically robust while still being simple to inspect and modify.
Control Law

How the controller is implemented

1-axis control

The one-axis controller uses a direct PD form, tau = -Kp * theta - Kd * omega, followed by saturation. That makes the effect of gain tuning and actuator limits easy to interpret in the angle, rate, and torque plots.

Quaternion control

The three-axis controller uses the vector part of the attitude quaternion together with body-rate feedback. In code, tau = sat(-Kp * qVec - Kd * w, tauMax), which is simple but still captures the essential structure of feedback attitude stabilization.

A useful detail here is that the controller explicitly enforces torque saturation in both modes. That means the transient plots are not idealized controller outputs; they show what happens when the requested torque is larger than the actuator can deliver.

Robustness

Monte Carlo evaluation and animation workflow

The Monte Carlo mode randomizes roll, pitch, and yaw uniformly between -30 and 30 degrees and draws initial body rates between -1 and 1 deg/s. For each run, the app propagates the quaternion model, computes the attitude-error history, records final pointing error, and estimates the first time the error drops below 1 degree.

  • The ensemble view overlays attitude-error histories so stability across runs can be inspected directly rather than reduced immediately to a single scalar metric.
  • Histograms summarize final pointing error and settling time, while a compact bar chart reports the mean final error, worst final error, and mean settling time.
  • A slider-based animation timeline lets the user scrub through either the 2D or 3D motion history, which is useful for relating transient plots to actual spacecraft orientation.
  • An auto-update option reruns the selected mode when parameters change, which makes the app behave more like a live design environment than a static homework script.

Engineering Takeaway

What this project demonstrates

This project shows real control-simulation thinking: state definition, quaternion handling, rate-feedback stabilization, actuator saturation, disturbance injection, randomized initial-condition testing, and human-readable visualization all inside one tool.

For a recruiter, the point is that this is more than a GUI and more than a controls derivation. It is a complete simulation product that turns aerospace dynamics into an interactive engineering artifact.
